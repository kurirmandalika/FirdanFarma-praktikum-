======================================================================
1. IDENTITAS DAN RINGKASAN APLIKASI
======================================================================

Aplikasi Apotek Firdan Farma adalah aplikasi desktop Windows untuk membantu
operasional apotek secara offline. Aplikasi ini digunakan untuk mengelola
master obat, stok, batch, tanggal kedaluwarsa, pembelian atau stok masuk dari
supplier, transaksi penjualan, kartu stok, stok opname, laporan, audit
aktivitas, manajemen pengguna, serta backup dan restore database.

Aplikasi dibuat dengan C# WinForms dan berjalan pada .NET Framework 4.8.
Data operasional disimpan pada database SQLite lokal. Fokus utama aplikasi
adalah menjaga agar stok, transaksi, laporan, dan histori perubahan tetap
akurat serta dapat ditelusuri kembali.

Aplikasi ditujukan untuk penggunaan pada satu komputer apotek secara offline.
Fungsi utama tidak membutuhkan koneksi internet.

3. TUJUAN APLIKASI
======================================================================

Aplikasi Apotek Firdan Farma dibuat untuk:

1. Mempercepat proses penjualan obat di kasir.
2. Menampilkan stok aktual setiap obat.
3. Mencatat stok masuk dari supplier secara terstruktur.
4. Mencatat nomor faktur supplier, batch, dan tanggal kedaluwarsa.
5. Menggunakan batch yang kedaluwarsanya paling dekat ketika penjualan.
6. Mencegah stok menjadi negatif.
7. Memisahkan laporan penjualan Tunai dan QRIS.
8. Menggunakan periode laporan dengan cut-off pukul 15.00.
9. Mencatat diskon sebelum transaksi diselesaikan.
10. Memberikan hak akses berbeda untuk Karyawan dan Super Admin.
11. Menyediakan histori mutasi stok yang dapat diperiksa kembali.
12. Menyediakan audit untuk mengetahui siapa melakukan apa, kapan, dan
    dampaknya terhadap data.
13. Menyediakan laporan operasional dan export Excel.
14. Menyediakan backup dan restore database lokal.
15. Menjaga histori lama tetap ada tanpa menghapusnya saat koreksi,
    pembatalan, atau migrasi database.

B. Mode Batch (Faktur)

- Nama obat.
- Satuan.
- Jumlah.
- Harga beli.
- Diskon.
- PPN.
- Harga jual.
- Nomor batch.
- Tanggal kedaluwarsa.

Ketentuan stok masuk:

- Obat yang belum ada dapat dibuat otomatis ke master saat submit.
- Supplier dan kategori tertentu dapat dibuat otomatis sesuai alur input.
- Obat yang sudah ada mendapatkan tambahan stok dan batch.
- Harga jual dapat berbeda pada setiap baris faktur.
- Nomor faktur duplikat ditolak pada mode faktur.
- Header dan seluruh detail faktur disimpan dalam satu transaksi database.
- Stok masuk membentuk kartu stok, laporan stok masuk, dan audit log.
- Histori stok masuk yang sudah tersimpan tidak diedit langsung untuk

7.6 Koreksi Stok

Koreksi Stok digunakan untuk menyesuaikan saldo berdasarkan pemeriksaan
fisik atau kejadian operasional. Koreksi dapat berupa delta positif atau
negatif.

Ketentuannya:

- Obat dan batch harus dipilih dengan benar.
- Jumlah tidak boleh menyebabkan stok negatif.
- Alasan wajib diisi.
- Koreksi dapat menambah atau mengurangi stok.
- Mutasi batch diarahkan sesuai aturan stok dan FEFO.
- Koreksi tercatat di kartu stok.
- Koreksi tercatat di audit log.
- Akses bergantung pada permission user atau role Super Admin.

7.7 Stok Opname

Stok Opname digunakan untuk membandingkan stok sistem dengan stok fisik.
Saat sesi dibuat, sistem mengambil snapshot yang mencakup:

- Obat aktif.
- Batch obat.
- Tanggal kedaluwarsa.
- Saldo setiap batch.
- Stok legacy tanpa batch.

Alur stok opname:

1. Membuat sesi opname baru.
2. Sistem membuat snapshot stok.
3. User mengisi stok fisik tiap item.
4. Stok fisik tidak boleh negatif.
5. Item yang memiliki selisih wajib diberi alasan.
6. Hitungan disimpan sebagai draft.
7. Super Admin memeriksa hasil.
8. Sesi diselesaikan untuk memposting selisih.
9. Selisih menjadi mutasi stok masuk atau stok keluar.
10. Hasil dapat diexport ke Excel dan tercatat di audit.

Selama sesi opname aktif, penjualan, stok masuk, pembatalan transaksi, dan
koreksi stok ditahan agar snapshot tetap akurat. Jika stok berubah selama
opname, penyelesaian dapat ditolak. Sesi selesai atau dibatalkan tidak dapat
diedit kembali.

Pada implementasi UI saat ini, menu stok opname ditampilkan untuk Super Admin.
Sebagian dokumen kebutuhan menyebut keterlibatan Karyawan dalam penghitungan
atau pengajuan, tetapi akses menu produksi saat ini belum menampilkannya untuk
Karyawan.

8. ATURAN BISNIS STOK DAN BATCH
======================================================================

8.1 Rumus stok ringkas

SISA = AWL + MSK - KLR

Keterangan:
- AWL  : stok awal.
- MSK  : total stok masuk.
- KLR  : total stok keluar.
- SISA : stok yang tersedia.

Sistem menjaga agar stok tidak pernah menjadi negatif.

8.2 Batch dan expired

Setiap obat dapat memiliki banyak batch. Batch menyimpan nomor batch, tanggal
kedaluwarsa, jumlah masuk, jumlah keluar, jumlah tersedia, supplier, dan
referensi stok masuk.

Penjualan memakai FEFO, yaitu First Expired First Out. Batch dengan tanggal
kedaluwarsa paling dekat digunakan lebih dahulu. Batch tanpa tanggal expired
dapat diperlakukan sebagai stok yang masih dapat dijual sesuai validasi sistem,
sedangkan batch yang telah expired ditolak dari penjualan.

8.3 Stok legacy tanpa batch

Data stok lama tanpa batch tetap dapat dikelola dan dijual. Ketika diperlukan
pengembalian stok dari pembatalan transaksi, sistem dapat membuat batch
pengembalian dengan nomor referensi RETUR-... untuk bagian stok legacy yang
tidak memiliki mapping batch asal.

8.4 Validasi stok

- Qty penjualan harus lebih dari nol.
- Qty stok masuk harus lebih dari nol.
- Harga beli dan harga jual tidak boleh negatif.
- Stok tidak boleh negatif.
- Batch expired tidak boleh dijual.
- Tanggal expired stok masuk tidak boleh lebih awal dari hari ini.
- Seluruh perubahan penting harus tercatat.

9. ATURAN PENJUALAN, PEMBAYARAN, DAN DISKON
======================================================================

9.1 Alur penjualan

1. User login.
2. User mencari obat.
3. User memasukkan jumlah dan menambahkan item ke keranjang.
4. Sistem memvalidasi stok dan kelayakan batch.
5. Sistem memilih batch secara FEFO.
6. Sistem menghitung subtotal.
7. User memilih Tunai atau QRIS.
8. Sistem menanyakan apakah ada diskon.
9. User memilih YA atau TIDAK.
10. Jika YA, user mengisi nominal diskon.
11. Sistem memvalidasi dan menghitung total akhir.
12. User mengonfirmasi transaksi.
13. Sistem menyimpan transaksi secara final.
14. Sistem mengurangi stok dan saldo batch.
15. Sistem membuat stock movement dan audit log.
16. Sistem membuat kode laporan T atau Q.
17. Struk dapat dipreview atau dicetak.

9.2 Metode pembayaran

Metode pembayaran utama hanya:

- TUNAI
- QRIS

Pembayaran lain tidak termasuk dalam flow utama aplikasi.

9.3 Diskon

Jika user memilih TIDAK:
- Diskon menjadi Rp0.
- Total akhir sama dengan subtotal.

Jika user memilih YA:
- User memasukkan nominal diskon.
- Diskon tidak boleh negatif.
- Diskon tidak boleh lebih besar dari subtotal.
- Total akhir = subtotal - diskon.
- Diskon tersimpan pada transaksi, laporan, dan audit.

9.4 Pencegahan transaksi ganda

Tombol simpan atau checkout dilindungi dari double-click agar satu tindakan
user tidak menghasilkan dua transaksi final.

9.5 Pembatalan transaksi

Transaksi final tidak diedit diam-diam. Pembatalan hanya dapat dilakukan oleh
Super Admin dan wajib mencantumkan alasan.

Saat transaksi dibatalkan:

- Status transaksi berubah menjadi DIBATALKAN.
- Stok dikembalikan.
- Batch asal dikembalikan bila mapping tersedia.
- Stok legacy dapat memakai batch pengembalian RETUR-... .
- Audit menyimpan user, waktu, alasan, nominal, metode pembayaran, dan
  before-after.
- Histori transaksi lama tidak dihapus.

Cara yang aman untuk salah input adalah membatalkan transaksi dengan alasan
lalu membuat transaksi baru yang benar.

10. PERIODE LAPORAN DAN KODE TRANSAKSI
======================================================================

10.1 Cut-off pukul 15.00

Hari laporan apotek tidak mengikuti pergantian tanggal kalender pada pukul
00.00. Periode laporan berganti pada pukul 15.00.

- Transaksi sebelum 15.00 masuk tanggal laporan hari kalender yang sama.
- Transaksi mulai 15.00 masuk tanggal laporan hari berikutnya.
- Histori transaksi lama tidak dihapus.
- Transaction datetime dan report date disimpan terpisah.

Contoh:

- 19 Agustus 2026 14:59 -> laporan 19 Agustus 2026.
- 19 Agustus 2026 15:00 -> laporan 20 Agustus 2026.
- 19 Agustus 2026 22:00 -> laporan 20 Agustus 2026.
- 20 Agustus 2026 08:00 -> laporan 20 Agustus 2026.

Perubahan jam Windows dapat menghasilkan peringatan satu kali per sesi. User
harus memastikan tanggal dan jam komputer benar sebelum bertransaksi.

10.2 Kode transaksi laporan

- Tunai menggunakan prefix T: T1, T2, T3, dan seterusnya.
- QRIS menggunakan prefix Q: Q1, Q2, Q3, dan seterusnya.
- Urutan Tunai dan QRIS terpisah.
- Nomor dimulai dari 1 pada tanggal laporan baru.
- Kode tidak boleh duplikat pada tanggal laporan yang sama.

10.3 Nomor internal

- transaction_no : PJ-yyyyMMdd-HHmmssfff-userId
- purchase_no    : PB-yyyyMMdd-HHmmssfff-userId
- opname_no      : SO-yyyyMMdd-HHmmssfff-userId
- report_code    : T1, T2, ... atau Q1, Q2, ...

User, role, waktu, aksi, entitas, referensi, before, after, nominal, diskon,

11.9 Stok opname

Sesi opname, status sesi, snapshot, item, stok sistem, stok fisik, selisih,
harga beli, nilai selisih, alasan, dan hasil posting.

======================================================================
15. BACKUP, RESTORE, MIGRASI, DAN KEANDALAN
======================================================================

Backup dibuat untuk menjaga database tetap dapat dipulihkan jika terjadi
kesalahan operator, kerusakan data, migrasi, atau operasi besar.

Backup manual:

1. Super Admin membuka menu Backup Data.
2. Sistem menyalin database aktif.
3. Lokasi file backup ditampilkan.
4. Aktivitas backup dicatat di audit.

Restore:

1. Super Admin memilih file database backup.
2. Sistem meminta konfirmasi.
3. Sistem membuat safety backup database lama.
4. Sistem mengganti database aktif dengan file pilihan.
5. Aktivitas restore dicatat di audit.
6. Aplikasi perlu ditutup dan dibuka kembali.

Migrasi database lama dilakukan dengan menjaga histori yang sudah ada. Backup
otomatis dibuat sebelum migrasi. SQLite lokal menggunakan WAL dan cocok untuk
penggunaan satu komputer, tetapi belum ditujukan untuk transaksi bersamaan
pada banyak terminal.

Export Excel berguna untuk laporan dan arsip. File Excel bukan pengganti
backup database karena tidak menyimpan seluruh struktur, relasi, dan histori
aplikasi.

20. KESIMPULAN
======================================================================

Aplikasi Apotek Firdan Farma adalah sistem operasional apotek desktop offline
yang menggabungkan kasir, manajemen obat, stok berbasis batch, expired date,
stok masuk supplier, laporan, audit, dan backup database dalam satu aplikasi.

Kekuatan utama aplikasi adalah pemisahan hak akses, pencatatan histori,
validasi stok, FEFO, cut-off laporan pukul 15.00, pemisahan kode Tunai dan
QRIS, audit before-after, serta kemampuan backup dan restore.

Aplikasi sudah memiliki inti operasional yang diperlukan untuk pengujian
lapangan. Sebelum go-live, pengujian Windows 7 SP1, printer client, seluruh
skenario acceptance, dan penyelarasan bagian dokumentasi yang berbeda dari UI
harus diselesaikan.
